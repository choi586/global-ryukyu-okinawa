# 글로벌류큐·오키나와연구소 홈페이지 개발기획서 v0.2

작성일: 2026-09-17

이 문서는 v0.1 검토 후 사용자와 확정한 1차 개발 범위를 반영한다. v0.1과 범위·운영 방식이 다른 경우 이 문서를 우선한다. 원본 문서는 보존한다.

## 1. 이번에 확정한 범위

- 메인화면, 공지사항, 관리자 기능만 우선 구현한다.
- 공지사항은 관리자가 게시판 형태로 등록·수정·삭제한다.
- 나머지 메뉴는 표시하되 비활성 상태로 둔다.
- 학교 서버는 아직 정해지지 않았다. 먼저 테스트 환경에서 구현·검증한다.
- 정식 운영 및 학교 서버 이전은 테스트 이후 별도로 결정한다.

## 2. 공개 화면과 주소

| 화면          | 주소                 | 1차 상태            |
| ------------- | -------------------- | ------------------- |
| 메인          | `/`                  | 활성                |
| 공지사항 목록 | `/news`              | 활성                |
| 공지사항 상세 | `/news/[slug]`       | 활성                |
| 연구소 소개   | 추후 `/about`        | 메뉴만 표시, 비활성 |
| 연구진        | 추후 `/people`       | 메뉴만 표시, 비활성 |
| 연구사업      | 추후 `/research`     | 메뉴만 표시, 비활성 |
| 학술행사      | 추후 `/events`       | 메뉴만 표시, 비활성 |
| 연구성과      | 추후 `/publications` | 메뉴만 표시, 비활성 |
| 아카이브      | 추후 `/archive`      | 메뉴만 표시, 비활성 |

1차 `/news`는 공지사항 전용이다. 연구소 소식 게시판은 후속 범위로 둔다.

비활성 메뉴에는 ‘준비 중’을 표시한다. 클릭·탭·키보드 입력으로 이동하거나 빈 페이지를 열지 않는다. 색상만으로 비활성 여부를 구별하지 않는다. 모바일 메뉴에도 동일하게 적용한다. 미완성 메뉴를 위한 기본 페이지 생성은 1차 필수 범위에서 제외한다.

## 3. 메인화면

- 공통 Header: 기관명 또는 로고, 전체 메뉴. 공지사항과 홈 이동만 활성화한다.
- Hero: 절제된 연구기관 이미지 또는 그래픽, 확인된 기관명과 소개 문구.
- 연구소 소개 요약: 제공된 소개문을 표시한다. 미제공 시 임시 문구임을 화면에서 구분한다.
- 연구분야 요약: 제공된 자료를 바탕으로 표시한다. 미구현 상세 페이지로 연결하지 않는다.
- 공지사항: 실제 게시판의 공개된 최신 글을 연동한다. 목록 및 상세로 이동할 수 있다.
- 연구성과·아카이브 영역: 디자인상 배치할 경우 ‘준비 중’으로 표시하며 가상의 실적을 실제 자료처럼 노출하지 않는다.
- 공통 Footer: 확인된 기관명·주소·연락처만 표시한다.

공지사항 외 콘텐츠의 관리자 편집 기능은 이번 범위에 포함하지 않는다. 다국어는 후속 범위이며 ENG/JPN 전환 버튼은 아직 표시하지 않는다.

## 4. 공지사항 기능

### 공개 화면

- 목록: 제목, 게시일, 상단 고정 표시, 페이지 이동.
- 정렬: 상단 고정 글 우선, 나머지는 게시일 내림차순.
- 상세: 제목, 게시일, 본문, 이미지, 첨부파일, 목록 돌아가기.
- 공개된 글만 방문자에게 제공한다.
- 글이 없을 때 안내문을 표시한다.
- 존재하지 않거나 공개되지 않은 글은 비로그인 방문자가 열 수 없게 한다.
- 검색은 후속 범위로 둔다.

### 저장 항목

- 고유 ID, 상세 주소용 slug, 제목, 본문.
- 작성일, 게시일, 수정일.
- 초안/공개 상태, 상단 고정 여부.
- 이미지 및 첨부파일 정보: 저장 위치, 표시 이름, 파일 유형, 크기, 이미지 설명.

본문 입력 형식과 업로드 허용 유형·용량은 구현 시 정하고 관리자 화면에 안내한다. 게시물은 DB에, 업로드 파일은 지속적으로 보존되는 파일 저장소에 저장한다. JSON/TypeScript 샘플 데이터는 디자인 검토용으로만 사용한다.

## 5. 관리자 기능

| 화면      | 주소                       | 기능                                              |
| --------- | -------------------------- | ------------------------------------------------- |
| 로그인    | `/admin/login`             | 관리자 로그인                                     |
| 공지 관리 | `/admin`                   | 글 목록, 초안/공개 상태 확인                      |
| 글 작성   | `/admin/notices/new`       | 제목·본문 입력, 이미지·첨부파일 업로드, 저장·공개 |
| 글 수정   | `/admin/notices/[id]/edit` | 수정, 공개 상태 변경, 삭제                        |

- 관리자만 글과 파일을 등록·수정·삭제할 수 있다. 화면 접근뿐 아니라 서버의 저장·삭제 요청에도 권한 검사를 적용한다.
- 로그아웃 기능을 제공한다.
- 삭제 시 대상 글을 명시하고 확인 절차를 제공한다.
- 회원가입, 방문자 계정, 댓글, 다중 권한 관리는 제외한다.
- 초기 관리자 계정은 별도 설정 절차로 준비하고 비밀번호·인증 키를 저장소나 공개 화면에 포함하지 않는다.
- 메인 편집, 연구진 관리, 다른 게시판 관리 메뉴는 이번 관리자 화면에서 제공하지 않는다.

## 6. 기술 및 테스트 배포 방향

- 홈페이지: Next.js App Router, TypeScript, React, Tailwind CSS.
- 원본 관리: GitHub.
- 테스트 배포: 추후 Cloudflare Workers에 연결한다.
- 관리자 인증은 서버에서 처리하고, DB는 D1, 파일 저장소는 R2를 사용한다. 현재는 로컬 테스트이며 연결 전이다.
- 게시물과 파일은 서버 재시작·재배포 이후에도 유지되어야 한다.
- 관리자 기능이 있으므로 전체 시스템을 정적 파일만으로 운영하는 방식은 1차 전제로 삼지 않는다.
- 콘텐츠 조회·저장 로직은 화면과 분리한다.
- 데이터와 업로드 파일을 내보내고 이전할 수 있는 구성을 사용한다.
- 학교 서버 사양이 확인되기 전에는 이전 방식이나 동일 기능의 즉시 이전을 보장하지 않는다.

## 7. 디자인·반응형·접근성

- 학술기관에 맞는 정돈되고 절제된 디자인을 유지한다.
- 참고 사이트의 정보 배치 방식을 참고하되 코드·이미지·디자인을 복제하지 않는다.
- 한국어 메뉴를 기본으로 한다.
- 데스크톱 1440px, 태블릿 768~~1024px, 모바일 375~~430px에서 확인한다.
- 모바일 가로 넘침이 없어야 하며 메뉴·공지 본문·첨부파일을 사용할 수 있어야 한다.
- 키보드 탐색, 초점 표시, 제목 계층, 이미지 대체 텍스트를 점검한다.
- 샘플 콘텐츠는 검토 화면에서도 샘플임을 명확히 표시한다.

## 8. 개발 순서

1. 프로젝트 기반 및 공통 Header/Footer 구성.
2. 메인화면과 활성·비활성 메뉴 구현.
3. 인증·DB·파일 저장소 연결 및 초기 관리자 설정.
4. 공지사항 등록·수정·삭제와 공개 목록·상세 연결.
5. 테스트 배포 및 모바일·권한·저장 지속성 검증.

## 9. 1차 완료 기준

- 메인화면과 공지사항 목록·상세가 정상 작동한다.
- 관리자가 로그인해 글과 첨부파일을 등록하고 공개할 수 있다.
- 공개·수정·삭제 결과가 방문자 화면에 반영된다.
- 비로그인 사용자의 관리 화면 접근 및 쓰기·삭제 요청이 차단된다.
- 초안은 방문자 목록 및 상세에서 노출되지 않는다.
- 재배포 후에도 게시물과 첨부파일이 유지된다.
- 나머지 메뉴는 PC·모바일 모두 ‘준비 중’으로 표시되고 이동하지 않는다.
- 빈 목록, 긴 제목, 이미지 없는 글, 잘못된 상세 주소를 적절히 처리한다.
- 빌드 오류와 주요 화면의 실행 오류가 없다.
- README에 실행법, 관리자 초기 설정, 콘텐츠 운영법, 테스트 배포법, 데이터·파일 이전 시 확인사항을 적는다.

## 10. 후속 범위

연구소 소개·연구진·연구사업의 상세 화면, 학술행사·연구성과·연구소 소식·아카이브 게시판, 다국어, 검색, 학교 서버 이전은 이후 단계에서 진행한다.

## 11. 구현 중 확정한 콘텐츠·디자인 변경 (2026-09-17)

- 기관 로고는 사용자가 제공한 실제 PNG를 사용한다.
- 공식 영문 명칭은 로고에 따라 `Global Institute for Ryukyu and Okinawa Studies`로 정정한다.
- 메인 소개와 비전은 `https://ccs.khu.ac.kr/laboratory/okinawa`의 내용을 근거로 작성하고 출처를 표시한다.
- 임시 슬로건과 임의의 연구분야는 삭제한다. 공식 페이지에 없는 사실을 만들어 추가하지 않는다.
- 경희대 메인 홈페이지의 글꼴과 디자인을 참고한다. Noto Sans KR·Roboto·Merriweather, 붉은 상단 띠, 흰색 메뉴 영역을 적용한다.
- 위 변경은 기존의 임시 소개문 및 연구분야 요약 지침보다 우선한다.


## 2026-09-17 변경 결정

- 티스토리를 기존 자료창고로 사용하며 NEWS / ACTIVITIES / PUBLICATIONS에 게시글과 사진을 재배치한다.
- 제목·본문·게시일은 원문을 유지하고 행사일·발행일은 근거가 있을 때만 구분한다.
- 사진은 원본 백업과 웹용 최적화 사본을 분리한다.
- 관리자가 세 영역의 게시물을 운영한다. 나머지 미구현 메뉴는 비활성 상태를 유지한다.
- Vercel과 Supabase 대신 추후 Cloudflare Workers / D1 / R2를 연결한다. 현재는 로컬 테스트이며 온라인 배포 전이다.


## 메인 캐러셀 운영

- `/admin`의 메인 캐러셀 관리에서 사진·포스터 추가, 교체, 삭제, 순서, 공개 여부를 설정한다.
- 제목·짧은 설명·선택 링크를 함께 저장하며 코드 수정과 재배포는 필요하지 않다.
- 공개 최대 5장(권장 3~5장), 비공개 포함 15장 보관.
- 5초 페이드 전환, 좌우 버튼·위치 표시·모바일 터치·자동재생 정지 버튼.
- 마우스 올림·키보드 조작·숨겨진 탭에서는 정지하고, 직접 넘긴 뒤에는 10초간 대기한다.
- 사진 원본 업로드를 웹용으로 자동 최적화한다. 포스터 전체 보기와 사진 채우기를 선택할 수 있다.
- Cloudflare에서는 정보는 D1(DB), 사진은 비공개 R2(MEDIA)에 저장한다. 로컬 검증은 SQLite와 파일을 사용한다.
- 공개 화면은 5초마다 새 설정을 확인한다. 비공개 사진 URL도 관리자 권한을 검사한다.
